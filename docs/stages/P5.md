## 一、交付与复现

P5 串通了 MiniMind 的文本与八码本事件、Mimi 分块解码和本地 WAV 写出。`stream_generate()` 每步交付文本 Token 或完整码本帧 `[1,8,1]`。`stream_waveform()` 每收齐一块就交付 CPU FP32 单声道 PCM `[samples]`，自然结束时冲刷剩余帧。关闭消费迭代器会释放本次解码状态与上游生成器。

使用已有的本地 MiniMind SFT、tokenizer 和 Mimi，在项目根目录激活 `.venv` 后执行。

```bash
python -m pip install -e '.[dev,media]'
HF_HUB_OFFLINE=1 HF_DATASETS_OFFLINE=1 python scripts/demo_p5.py '你好，请用一句话介绍春天。' --device cpu --chunk-frames 4
HF_HUB_OFFLINE=1 HF_DATASETS_OFFLINE=1 python scripts/check_p5.py --device cpu --chunk-frames 4 --repeats 3
```

Demo 在首块到达时创建 WAV，后续逐块写入。默认路径带 run ID，也可以用 `--output` 指定新文件。`--no-cache` 控制 Thinker/Talker KV，用于对照。分块解码沿用同一话轮内的 Mimi KV，两项缓存分别管理。

## 二、接口与实现

| 模块 | 契约 |
| --- | --- |
| `OmniPlusModel.forward_embeddings()` | 输入 `[B,T,D]` 与覆盖历史和当前 Token 的 `[B,P+T]` mask，返回归一化后的 hidden、当前 position IDs、Thinker Cache、aux loss 与按需选取的 Bridge 特征 |
| `OmniPlusOmni.forward()` | 处理模态特征注入和 Talker 条件，公开 Cache 仍按 Thinker、Talker 的层序拼接，Bridge 仍使用指定 Block 归一化前的输出 |
| `OmniPlusOmni.stream_generate()` | 单话轮 batch=1，支持有效 prompt 前的左 padding，发出 `(token, frame)`；文本 EOS 后继续生成待完成的音频尾部 |
| `MimiStreamingDecoder` | 每话轮独立保存 decoder Transformer KV 和有限卷积历史。复用本地 Mimi 的 quantizer、上采样、Transformer 与波形 decoder |
| `stream_waveform()` | 按码本帧顺序凑块和冲刷，输出 `WaveformEvent`，由调用方消费文本与波形 |

本地 Mimi 是常量左填充、右裁剪的单声道因果配置。流式解码从配置推导卷积历史，并保留 1 个量化帧和最多 9 个 decoder latent。Transformer KV 保持完整历史，内存随话轮长度增长。该路径依赖已验收的 Transformers 4.57.6 Mimi 子模块结构。 [Mimi 实现](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/models/mimi/modeling_mimi.py)

## 三、性能计时口径

真实 MiniMind Dense Omni SFT 与本地 Mimi 在 CPU FP32 上执行。短、长两条提示分别对 Cache On/Off 预热一次，交替计时各 3 次。两路均为贪心采样，最多 256 步。Mimi 为 24 kHz，每帧对应 1,920 采样点，4 帧整块覆盖 320 ms 音频。

| 指标 | 测量范围 |
| --- | --- |
| TTFT | 从文本请求开始到首个非特殊文本 Token 事件 |
| TTFA | 从文本请求开始到首个非空 PCM 块 |
| 模型耗时 | 推进模型生成器的累计墙钟时间，含前向、采样和码本对齐 |
| 端到端耗时 | 热启动下从模板和分词到 PCM 事件流结束，模型加载、写盘和播放分别在计时边界之外 |
| RTF | 模型或端到端耗时除以实际 PCM 音频时长 |
| P95 块间隔 | 连续 PCM 块到达间隔的单次请求 P95，包含最后一个短块，表中汇总 3 次中位数 |
| 峰值内存 | 进程 RSS 的累计高水位，含权重与所有运行，按进程报告 |

### 1 实测结果

Apple M5，24 GiB 内存，macOS arm64，CPU 4 线程，Python 3.12.14、PyTorch 2.15.0、Transformers 4.57.6。下表为各模式 3 次重复的中位数。冷加载用时 1.55 秒，进程峰值 RSS 为 1,587 MiB。原始计时、模型配置、权重和源码 SHA 保存在基准记录。 [CPU FP32 实测 JSON](../../experiments/p5/cpu-fp32-20261105.json)

| 短，3.84 s | On | 16.2 | 115.7 | 0.497 | 0.700 | 0.182 | 59.1 |
| 短，3.84 s | Off | 17.4 | 203.0 | 1.303 | 1.492 | 0.388 | 127.6 |

### 2 输出与停止验证

- 短回复用 57 步生成 17 个文本 Token 和 48 帧，长回复用 134 步生成 40 个文本 Token 和 125 帧。两者均在步数预算前自然停止，Cache On/Off、重复请求和左侧 3 个 padding 的文本与码本逐元素一致。
- 短、长回复分块 PCM 对比整段解码的最大绝对差分别为 2.00e-6 和 1.18e-6，均通过 `rtol=1e-4, atol=1e-4`。
- 13 步预算截断保留 5 个完整声学帧，按 `[4,1]` 两块交付。极小 Codec 测试覆盖尾块、取消、第二话轮独立状态及仅文本结束。
- Demo 实际写入 32 个音频块。回读为 240,000 个样点、24 kHz、单声道 PCM16。 [本地 Demo WAV](../../outputs/p5/demo-20261105.wav)

本基准覆盖同设备的两条 T2A 请求。音质、播放端延迟及跨任务统计留给后续正式评测。

## 六、下一阶段接口交接

Qwen 适配以独立 Backbone 处理词表、模板、位置与 Cache。第一步使用同一 Qwen 权重对照原生 Transformers 的 prefill、逐步 decode 与 logits，再把选定 hidden state 接入 Bridge。MiniMind 的 `forward_embeddings()` 和现有严格加载结果提供对照基线。

Qwen 的文本切分会改变文本与声学标签在联合序列中的位置。重新构造标签时间轴后，按冻结 Thinker、训练 Bridge/Talker、对齐两种 Projector 的顺序验收 T2A、A2A、I2T。正式对照固定独立测试集、设备、精度、采样、训练预算与种子，按各自 tokenizer 记录输入和输出 Token 数。
