## 二、文件与实现审核

| 文件 | 职责与改动 |
| --- | --- |
| `omni/models/thinker/backend.py` | 定义 `ThinkerBackend` 和 `BackboneOutput`，统一文本 logits、单层表示与原生 Cache |
| `omni/models/thinker/qwen_backend.py` | 注入官方 `Qwen3ForCausalLM`，复用 embedding、原生前向及 LM head，补齐左 padding 的逻辑位置 |
| `configs/assets_v2.yaml` | 锁定官方模型 revision、路径、许可证、文件字节数与 SHA-256 |
| `configs/model/qwen3_1_7b.yaml` | 预先固定 CPU FP32、误差阈值、seed、生成上限和 thinking 模式 |
| `scripts/check_qwen_backend.py` | 离线验收本地文件、加载信息、模板、原生与 Backend 数值及短生成，成功后写独立 manifest |
| `tests/test_qwen_backend.py` | tiny Qwen 离线测试，覆盖原生对照、显式和默认位置、Cache、冻结输入梯度和异常后清理 |

审核发现 Transformers 4.57.6 的 `output_hidden_states=True` 会临时包装层的 `forward`，原生前向抛错时可能留下一层包装。Backend 改用只在当次调用注册的单层 hook，按调用线程采集，正常退出和异常退出均移除 hook。专项测试先触发越界 ID 异常，再确认原方法和 hook 数保持，随后重试成功。该实现也能直接取得最后一层的归一化前表示。

Adapter 不改变参数值或绑定关系。加载和设备由调用方负责，`eval()` 和冻结参数分别控制。tiny 测试冻结官方 Qwen 参数后，选层损失仍可回传到输入 embedding。真实权重验收在 `inference_mode()` 下执行，未启动优化器或训练。 [Backend](../../omni/models/thinker/qwen_backend.py) · [专项测试](../../tests/test_qwen_backend.py)

## 三、资产、模型与 Tokenizer

官方非 Base `Qwen/Qwen3-1.7B`，revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`，Apache-2.0。使用现有 Hugging Face CLI，将 12 个原始文件下载到忽略目录 `weights/qwen3-1.7b/`，共 4,079,450,110 字节。文件包含两片 Safetensors、权重索引、tokenizer、内置 chat template、配置和许可证。12 个文件的字节数与 SHA-256 全部通过，两个大分片与官方 LFS 指纹一致。传输使用公开文件端点，推理在本地离线运行。 [固定官方版本](https://huggingface.co/Qwen/Qwen3-1.7B/tree/70d244cc86ccca08cf5af4e1e306ecf908b1ad5e) · [资产锁](../../configs/assets_v2.yaml)

| 配置 | 核对内容 |
| --- | --- |
| 官方模型结构 | 1,720,574,976 个参数，隐藏维 2048，28 个 decoder block，16 个 Q head、8 个 KV head，head dim 128，MLP 中间维 6144 |
| 权重与运行精度 | 两片 Safetensors 的 311 个序列化张量均为 BF16。原始 embedding 和 LM head 张量字节相同，HF 加载为 CPU FP32 后保持绑定 |
| 模型词表与 tokenizer | 模型 151936 行，tokenizer 151669 项，ID 0–151668，保留 267 个对齐行 |
| 文本标记 | `<\|endoftext\|>` 151643，`<\|im_start\|>` 151644，`<\|im_end\|>` 151645，`<think>` 151667，`</think>` 151668 |
| 生成约定 | tokenizer 的 PAD 为 151643、EOS 为 151645，官方生成配置 EOS 为 `[151645, 151643]`，tokenizer 本身无独立 BOS，模型生成配置 BOS 为 151643 |
| 模板 | 验证 thinking 两种模板后缀和直接 tokenize 的一致性。贪心烟测固定关闭 thinking，空 `<think>` 段由模板提供 |

## 五、实测结果

macOS arm64，Python 3.12.14，PyTorch 2.15.0，Transformers 4.57.6，Hugging Face Hub 0.36.2。真实 1.7B 对照固定 CPU FP32、SDPA、4 线程、seed 42，`rtol=1e-4`、`atol=1e-4`。HF 仅用本地文件，缺失、多余、不匹配权重键和加载错误均为零。 [1.7B 实测 manifest](../../experiments/r1/20261106-cpu-fp32/manifest.json)

| 对照 | 结果 |
| --- | --- |
| 原生 HF 对 Backend prefill | logits `[2,26,151936]`、第 13 层 `[2,26,2048]`，最大绝对差均为 0 |
| 输入 embedding 与位置 | `input_ids` 对 `inputs_embeds`、尾 logits、选层完整时间轴、原生裸 forward 的物理位置对照，最大差均为 0 |
| 左 padding 对逐样本 | 两条有效长度为 22 和 26，去除 padding 后 logits 与选层表示最大差均为 0 |
| 末层归一化边界 | 对 Backend 末层原始表示应用官方 RMSNorm，与 HF `hidden_states[-1]` 最大差为 0 |
| 原生 HF 对 Backend decode | prefill K/V `[2,8,26,128]`，decode 后长度 27。物理位置为 26，逻辑位置分别为 22 和 26。logits 和第 13 层最大差均为 0 |
| KV Decode 对无 Cache 重放 | logits 最大差 `6.00815e-5`，第 13 层最大差 `3.81470e-5`，均通过既定容差 |
| 多轮 Cache 重置 | 用 41 个 Token 重建对话前缀，产生新 Cache，旧 Cache 长度保持 27。与独立原生前向的尾 logits 最大差为 0 |
| 中英文短生成 | 固定 greedy、关闭 thinking、最多 12 个新 Token。中文为「巴黎」，英文为 `Paris`，两条均生成官方 EOS。HF generate、Backend 有 Cache 和无 Cache 的输出 ID 逐项相同 |

## 六、R2 接口交接

| 接口 | 已确定的约定 |
| --- | --- |
| 模态注入 | 二选一传入 `input_ids` `[B,T]` 或 `inputs_embeds` `[B,T,2048]`。R2 通过原生 embedding 获得文本序列，音频 `512→2048`、图像 `768→2048`，再校对媒体占位与样本有效长度 |
| 选层与 Bridge | `hidden_layer` 为零基 block 索引 `0–27`。输出 `[B,T,2048]` 是 block 后、最终 RMSNorm 前的原始表示。R1 对照使用第 13 层，末层也验证了 RMSNorm 边界。R2 决定实际层，并由 Fixed Bridge 负责 `2048→768` |
| Logits | 默认输出 `[B,T,151936]`，`logits_to_keep=1` 时为 `[B,1,151936]`。选层时间轴保持本次输入的完整 `T`，语言 loss 在外层对齐一次 |
| Cache | HF `DynamicCache` 的 K/V 布局为 `[B,8,P,128]`。本次输入长度为 `T`，完整 mask 为 `[B,P+T]`。物理位置按 `P..P+T-1` 追加，逻辑位置按有效 Token 编号；有左 padding 时后续每步带完整 mask |
| 生命周期 | Qwen cache 可原地更新，独立话轮传 `None`。发生错误后丢弃可能部分更新的 cache。Talker 与 Mimi 在 R2 分别持有自己的状态 |
| 特殊 Token | R1 保留官方 tokenizer 和 embedding/head。R2 再决定媒体标记与冻结策略，独立处理文本 EOS、音频 STOP、padding 和 loss ignore |

本轮范围为短文本、左 padding 与 append-only DynamicCache。R2 的多模态时轴、Mimi 音频、长上下文和训练须各自实测。 [R2 迁移任务](../reports/R0-migration-map.md)
